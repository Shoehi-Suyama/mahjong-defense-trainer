# 麻雀 守備判断トレーニング

相手の河・自分の手牌・場に見えている牌から「最も放銃しにくい牌」を選ぶ練習アプリ。
安全牌を暗記するのではなく、**なぜその牌が安全なのか / 何に対して安全で、何が危険として残るのか**
を毎回言葉で確認することを学習の中心に置く。

## 実装状況

### Phase 1（仕様書 §79）

- 牌の表示（SVG。`src/ui/tileFace.tsx` が唯一の絵柄供給元。将来ここへ牌画像スプライトを差し込める）
- 自分の手牌 / リーチ者の河 / 副露 / ドラ表示牌 / 巡目 / リーチ状態の表示
- 手牌をタップして 1 枚選択 →「この牌を切る」で回答
- 安全判定エンジン（`src/core/safety/`）
  - 現物 / ダブル現物 / 4枚見え
  - スジ（片スジ・中スジ・端牌スジ）
  - 壁（ノーチャンス）/ ワンチャンス
  - 字牌（見えている枚数）/ 端牌 / 序盤の外側
  - 「完全安全」と「相対的に安全（★1〜5・score）」を分離
- 回答後: 判定（正解 / 惜しい / 危険）、★の目安、理由の自動生成、
  「他の牌ではなくこの牌」の比較、安全度ランキング、残っている危険な待ち
- テーマ駆動の問題生成（`src/generator/`）＋ 品質検査（正解の存在・明確さ・牌枚数など）
- 学習モード（守備の基本）
- 成績記録・テーマ別正解率・苦手テーマの重点出題・回答時間

### Phase 2（追加）

- 「場に見えている牌」ストリップ（壁・ワンチャンス問題が一目で分かる）
- ドラ表示（仕様 §40）: 手牌のドラ牌にマーク。無スジのドラを切ると解説で警告
- 複数リーチ / ダブルリーチ（仕様 §77）
  - `double_riichi` テーマ、複数の河を表示
  - 相手ごとの安全度を回答後に並べて表示
  - 「片方の現物でももう片方には無スジ」という罠牌を distractor に配置
  - 学習モードに「複数リーチへの対応」「ドラの扱い」を追加

### Phase 3（追加）

- 副露（`furo`）テーマ（仕様 §39, §43）
  - 鳴いている相手（リーチなし・テンパイ気配）。`Opponent.tenpaiLikely` で警戒対象に
  - 鳴かれた 3 枚を壁・ワンチャンスの枚数に加算（副露牌で端牌がノーチャンスになる問題）
  - 役牌ポンなら「はっきり和了狙い」と解説で明示
- 序盤の外側（`early_read`）テーマ（仕様 §21, §45）
  - 相手が 1 巡目に切った数牌の外側を、確定情報でない弱い根拠（★2）として最善手に
- 学習モードに「副露相手への対応」「序盤の外側（河読み）」を追加

### Phase 4（追加）押し引きモード（仕様 §49, §50）

- 安全牌トレーニングとは別モード（`src/core/pushfold/`, `src/generator/pushfold.ts`）
- 自分はテンパイ、相手はリーチ。ツモ牌（危険牌）を切って押すか、降りるかを選ぶ
- 押し引き判定エンジン: 和了率 × 打点 と 放銃率 × 相手の平均失点（約 5000）を
  比較して期待値の目安を出す。放銃率は SafetyAnalyzer のツモ牌評価から算出
- 回答後に期待値の内訳・計算式・ツモ牌の危険度解析を表示
- 局面プロファイル（明確に押し／明確に降り／際どい）を先に決めてから生成し、
  clear_* は判定と食い違うものを捨てる
- 学習モードに「押し引きの考え方」、成績にテーマ別の押し引き正解率を追加
- ※ 簡易モデルであることを画面上で明示（点棒状況・ウラドラ期待は未考慮）

### Phase 4b（追加）実戦形式（仕様 §66, §67）

- 1 局を通して、河が伸びる中で **3 回続けて** 守備の判断をする（`src/core/live.ts`, `src/generator/live.ts`）
- 分岐ごとに河が 3 枚ずつ増え、増えた牌をハイライト。手牌は「理想手順で最善手を切った」前提で更新
- 各分岐は安全判定エンジンで独立に「明確な最善手がある」ことを検証（最善手レベルの下限 4→3→2）
- 各判断を ★の目安で採点（完全安全100 / 高80 / 中55 / 低30 / 危険0）、局末に守備スコアとふり返り
- 学習モードに「守備の思考手順（実戦形式）」、成績に実戦形式の正解率を追加

安全度・正解はすべてプログラム（判定エンジン）が決定し、AI には委ねない（仕様 §72）。

## 開発

```bash
npm install
npm run dev       # 開発サーバ
npm test          # 安全判定エンジン + 問題生成のテスト（vitest）
npm run build     # 型チェック + 本番ビルド
```

## デプロイ

`main` への push で `.github/workflows/deploy.yml` が `npm test` → `npm run build` →
GitHub Pages へ公開する。GitHub リポジトリ側で Pages を「GitHub Actions」に設定しておく。
